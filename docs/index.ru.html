Обзор

bbaccounts реализует OAuth 2.0 authorization code grant с PKCE. Выдаются непрозрачные Bearer-токены, а не JWT; проверяйте их через endpoint user info. Каждый ключ привязан к одному проекту.

Нужен ли свой authorization server? Нет. bbaccounts — это authorization server. Ваше приложение перенаправляет пользователя в bbaccounts, получает authorization code и обменивает его на токены на своём backend.

EndpointМетодНазначение
/oauth/authorizeGETНачать авторизацию, показать вход или согласие
/oauth/authorizePOSTОтправить решение на экране согласия
/oauth/tokenPOSTОбменять code или refresh token
/oauth/userinfoGET, POSTПрочитать авторизованный профиль
/oauth/revokePOSTОтозвать access или refresh token
/api/guardGETПрочитать секрет Guard и текущий код

Все production URL используют https://. Базовый URL этого инстанса: https://bbaccounts.unaux.com.

Прямые запросы

Client secret — это НЕ access token

Не передавайте client_secret как Authorization: Bearer или ?access_token=. Client secret используется только при обмене authorization code на токены.

Как получить access token

  1. Создайте проект в Developer, укажите Redirect URI/scopes и создайте credential. Сохраните client_id и client_secret (для confidential-клиентов).
  2. Перенаправьте пользователя на GET /oauth/authorize?response_type=code&client_id=...&redirect_uri=...&scope=profile%20email&state=...&code_challenge=...&code_challenge_method=S256.
  3. После редиректа обменяйте code на сервере: POST /oauth/token с grant_type=authorization_code, code, redirect_uri, client_id, code_verifier и client_secret для confidential-клиентов.
  4. Ответ содержит access_token (~1 час) и refresh_token. Используйте токен: Authorization: Bearer <access_token> или ?access_token=...

Когда у вас есть access token, любой endpoint — это обычный HTTPS-запрос к домену. SDK не нужен. Токен идентифицирует аккаунт; отдельно передавать ID аккаунта для token-based endpoint’ов не нужно.

Токен можно передать тремя способами (все поддерживаются):

# 1) Authorization header (recommended)
curl -i "https://bbaccounts.unaux.com/oauth/userinfo" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# 2) Query parameter
curl -i "https://bbaccounts.unaux.com/oauth/userinfo?access_token=ACCESS_TOKEN"

# 3) token= query parameter (alias)
curl -i "https://bbaccounts.unaux.com/api/profile?username=timinside"

На shared-хостинге некоторые прокси убирают заголовок Authorization. Если получаете invalid_token при валидном токене, повторите запрос с ?access_token=... или ?token=.... Также отправляйте User-Agent; некоторые хосты отдают anti-bot страницу запросам без него.

Ограничение unaux.com / ProFreeHost: этот хостинг может показать JavaScript anti-bot проверку (aes.js, ставит cookie __test) до запуска PHP. Обычный curl не выполняет JavaScript, поэтому запрос может не дойти до API bbaccounts. Простой обход: используйте Python stdlib скрипт ниже (examples/python/bb-unaux.py, без pip) для автоматического решения challenge, или переиспользуйте browser cookie __test в curl. Это ограничение хостинга, не проблема токена API.

Обходные пути для curl:

# 1) Reuse the __test cookie from your browser (works until the cookie expires/IP changes).
#    Open https://bbaccounts.unaux.com/ in a browser, pass the challenge, then copy the __test cookie
#    value from DevTools -> Application/Storage -> Cookies.
curl -i -A "Mozilla/5.0" \
  -H "Cookie: __test=PASTE_COOKIE_VALUE_HERE" \
  "https://bbaccounts.unaux.com/oauth/userinfo?access_token=ACCESS_TOKEN"

# 2) Save/reuse cookies with a cookie jar (useful after you have a valid __test cookie).
curl -i -A "Mozilla/5.0" -c bb-cookies.txt -b bb-cookies.txt \
  -H "Cookie: __test=PASTE_COOKIE_VALUE_HERE" \
  "https://bbaccounts.unaux.com/api/profile?username=timinside"

# 3) POST example with browser-like headers + __test cookie.
curl -i -A "Mozilla/5.0" \
  -H "Cookie: __test=PASTE_COOKIE_VALUE_HERE" \
  -H "Content-Type: application/json" \
  -X POST "https://bbaccounts.unaux.com/api/points?access_token=ACCESS_TOKEN" \
  -d '{"amount":10}'

Python (без pip, только stdlib) — решает challenge автоматически:

Скачать bb-unaux.py v1.0

Сохраните файл и запустите его через Python 3. Без pip-зависимостей. Также доступен как examples/python/bb-unaux.py в репозитории.

# Linux / macOS
python3 bb-unaux.py "https://bbaccounts.unaux.com/api/profile?username=timinside"
python3 bb-unaux.py "https://bbaccounts.unaux.com/api/points?access_token=ACCESS_TOKEN" POST '{"amount":10}'

# Windows cmd
python bb-unaux.py "https://bbaccounts.unaux.com/api/profile?username=timinside"
python bb-unaux.py "https://bbaccounts.unaux.com/api/points?access_token=ACCESS_TOKEN" POST "{\"amount\":10}"

Для надёжного серверного доступа отключите challenge для /api/* и /oauth/* в панели хостинга, если это возможно, или поставьте домен/прокси, который проксирует запросы напрямую в PHP. На браузерные пользовательские сценарии это не влияет.

# Normal examples (work when no anti-bot challenge is in front of PHP)
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/oauth/userinfo?access_token=ACCESS_TOKEN"

# POST with JSON body and Authorization header
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/points" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"amount":10}'

# POST with token in query
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/points?access_token=ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"amount":-5}'

/oauth/userinfo использует одобренные вами scope. Endpoint’ы /api/* требуют соответствующий scope верифицированного проекта: profile, points, friends, badges или teams. Отсутствующий scope возвращает insufficient_scope.

Guard API

Scope guard позволяет верифицированному companion-приложению читать TOTP-секрет аккаунта и текущий код, чтобы показывать rotating code локально. Сначала включите Guard в Аккаунт → Безопасность.

GET https://bbaccounts.unaux.com/api/guard
Authorization: Bearer ACCESS_TOKEN

Ответ содержит enabled, secret, code, digits, period и expires_in. Введите показанный код в форме входа для подтверждения; каждый код принимается один раз.

На том же компьютере запуск bbaccounts --service позволяет странице входа запрашивать подтверждение через desktop-окно. Установите guard.service_url в http://localhost:53683/confirm в config.local.php; на hosted-установке оставьте пустым. Страница отправляет {"email","app","ip","user_agent"} и ожидает {"approved":true}. Отказ или недоступный сервис возвращает к полю кода.

Процесс авторизации

  1. Ваше приложение создаёт PKCE verifier и отправляет пользователя на endpoint авторизации с S256 challenge и значением state.
  2. bbaccounts при необходимости выполняет вход, затем показывает экран согласия, если подходящее согласие ещё не дано.
  3. После одобрения браузер возвращается на ваш зарегистрированный redirect URI с одноразовым code и вашим неизменённым state.
  4. Ваш сервер обменивает code и verifier на access token и refresh token.
  5. Вызовите /oauth/userinfo с access token. Обновите токен до истечения часа.

Authorization code живёт 10 минут и используется один раз. Access token живёт 1 час. Refresh token живёт 30 дней и ротируется при каждом использовании.

Запрос авторизации

Отправьте браузер на этот endpoint как навигацию верхнего уровня:

GET https://bbaccounts.unaux.com/oauth/authorize
  ?client_id=YOUR_CLIENT_ID
  &redirect_uri=https%3A%2F%2Fapp.example.com%2Fcallback
  &response_type=code
  &scope=profile%20email
  &state=RANDOM_NONCE
  &code_challenge=BASE64URL_SHA256_OF_VERIFIER
  &code_challenge_method=S256
ПараметрОбязательныйПримечания
client_idдаClient ID credential’а со страницы проекта
redirect_uriдаДолжен точно совпадать с зарегистрированным URI
response_typeдаПоддерживается только code
scopenoПо умолчанию profile email
stateрекомендуетсяВозвращается без изменений; сравните со сохранённым значением
code_challengeрекомендуется43-128 символов после base64url-кодирования. Обязательно для public-клиентов
code_challenge_methodnoПо умолчанию S256; plain принимается при challenge длиной 43+ символа
promptnoconsent принудительно показывает экран согласия снова

Отказ или некорректный запрос возвращают редирект с error и error_description. Если неверен сам client ID или redirect URI, bbaccounts покажет страницу ошибки вместо редиректа, потому что назначение нельзя считать доверенным.

Обмен токена

Обменяйте code серверным запросом. Аутентифицируйтесь через HTTP Basic или передайте credentials в теле запроса.

POST https://bbaccounts.unaux.com/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=RETURNED_CODE
&redirect_uri=https%3A%2F%2Fapp.example.com%2Fcallback
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET
&code_verifier=YOUR_PKCE_VERIFIER

Ответ:

{
  "access_token": "…",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "…",
  "scope": "profile email"
}

Запрос должен повторять тот же redirect_uri, что использовался при авторизации. Если code был выдан с challenge, verifier обязателен. Public-клиент может не передавать secret только при использовании PKCE.

Информация о пользователе

Returns the account that owns the access token. You do not pass a username or account ID here; the token already identifies the account. 

# Recommended: Authorization header
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/oauth/userinfo" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Also works: token in URL
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/oauth/userinfo?access_token=ACCESS_TOKEN"

# Also works: POST
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/oauth/userinfo" \
  -H "Authorization: Bearer ACCESS_TOKEN"

Поля зависят от выданных scope:

{
  "sub": "42",
  "display_name": "Example User",
  "username": "example_user",
  "description": "Builds small tools.",
  "avatar_url": "https://bbaccounts.unaux.com/avatar/42.svg",
  "email": "user@example.com",
  "email_verified": false,
  "social": { "github": "octocat" },
  "updated_at": "2026-11-09T12:00:00+00:00"
}

sub — стабильный ID аккаунта. Храните его как внешний идентификатор; email может измениться. email_verified всегда false в этом инстансе, потому что отправка email не настроена.

social сопоставляет каждого подключённого провайдера с его username. Главный переключатель — Профиль → Приватность, а каждый провайдер включается отдельно в Аккаунт → Подключения.

Обновление токена

POST https://bbaccounts.unaux.com/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&refresh_token=CURRENT_REFRESH_TOKEN
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET

Ответ имеет тот же формат, что и обмен code. Оба токена заменяются: сохраните новый refresh token, потому что старый перестанет работать. Неудачный refresh означает, что пользователь должен авторизоваться снова.

Отзыв токена

POST https://bbaccounts.unaux.com/oauth/revoke
Content-Type: application/x-www-form-urlencoded

token=ACCESS_OR_REFRESH_TOKEN
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET

Отзыв access token или его refresh token инвалидирует пару. Пользователи также могут отозвать весь проект на странице авторизованных приложений — это сразу удалит согласие, токены и неиспользованные коды.

Десктопные и нативные приложения

Desktop, CLI и single-page приложения не могут хранить client secret. Создайте credential с включённым Public client, используйте PKCE с S256 и не передавайте client_secret при обмене code и обновлении токенов.

Открывайте страницу авторизации в системном браузере, а не во встроенном web view. Слушайте loopback-адрес и зарегистрируйте этот точный URI в проекте. Фиксированный порт упрощает точное совпадение; в примере ниже используется http://localhost:53682/callback.

POST https://bbaccounts.unaux.com/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=RETURNED_CODE
&redirect_uri=http%3A%2F%2Flocalhost%3A53682%2Fcallback
&client_id=PUBLIC_CLIENT_ID
&code_verifier=YOUR_PKCE_VERIFIER

Храните access и refresh token’ы в хранилище credentials ОС: DPAPI или Credential Manager в Windows, Secret Service в Linux. Пример в examples/desktop — Windows-only WinForms net10.0-windows приложение с HttpListener и DPAPI. Папки examples/php-web и examples/python содержат минимальные web-примеры без зависимостей.

Points API

Чтение или изменение баланса очков аккаунта-владельца токена. Токен идентифицирует аккаунт; ID аккаунта передавать не нужно. Требуется верифицированный проект и scope points.

# Read balance
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/points" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Add 10 points
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/points" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"amount":10}'

# Spend 5 points (token in URL also works)
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/points?access_token=ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"amount":-5}'

Ответ: {"points": 42}. Amount должен быть ненулевым целым числом от −10 000 до 10 000. Баланс не опускается ниже нуля.

Friends API

Управляйте списком друзей владельца токена. Токен идентифицирует аккаунт. Требуется верифицированный проект и scope friends.

# List friends
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/friends" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Send friend request by username
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/friends" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"timinside"}'

# Remove friend / cancel request (42 is the friend's account ID)
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/friends/42/remove" \
  -H "Authorization: Bearer ACCESS_TOKEN"

GET возвращает count, limit, friends, incoming и outgoing. POST /api/friends возвращает state: sent, pending, accepted или friends.

Profile API

Прочитать публичный профиль. Передайте username, чтобы выбрать аккаунт. Без токена возвращаются только публичные базовые данные профиля. С токеном верифицированного проекта (scope profile) токен определяет, кто запрашивает; не указывайте username, чтобы прочитать профиль владельца токена.

# Read a public profile without an access token
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/profile?username=timinside"

# Read your own profile (account identified by token)
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/profile" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Read another account with token (friend/self can see full private fields)
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/profile?username=timinside" \
  -H "Authorization: Bearer ACCESS_TOKEN"

Приватные профили возвращают только аватар, баннер, фон, отображаемое имя и username; остальные поля — none, если зритель не владелец и не принятый друг. Неизвестные аккаунты возвращают 404.

Badges API

Создавайте и выдавайте бейджи для вашего верифицированного проекта. Требуется scope badges. Бейджи создаются на странице настроек проекта или через этот API. У каждого бейджа есть числовой id — используйте его для выдачи.

# List project badges
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/badges" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Create a badge
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/badges" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Beta Tester","description":"Tested the beta"}'

# Issue badge by badge ID to a user by username
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/badges/12/issue" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"timinside"}'

Повторная выдача бейджа безопасна. Проект может выдавать только свои бейджи. Endpoint выдачи принимает ID бейджа в URL.

Cells API

Храните небольшие данные проекта в cells. Требуется верифицированный проект и scope cells. У каждой cell есть числовой id, key и value до 256KB. Cell может быть привязана к проекту или к пользователю (username).

EndpointМетодНазначение
/api/cellsGETСписок cells (фильтр по username, key, scope=project)
/api/cellsPOSTСоздать или обновить cell по ключу (upsert)
/api/cells/{id}GETПрочитать cell вместе со значением
/api/cells/{id}PUT/POSTОбновить значение cell
/api/cells/{id}DELETEУдалить cell
 
# Create/update a project-scoped cell
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/cells" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key":"welcome_message","value":"Hello!"}'

# Create/update a user-bound cell
curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/cells" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key":"save_slot_1","value":"{\"level\":3}","username":"timinside"}'

# List cells for a user
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/cells?username=timinside" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Read / update / delete by cell ID
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/cells/42" -H "Authorization: Bearer ACCESS_TOKEN"
curl -i -A "MyApp/1.0" -X PUT "https://bbaccounts.unaux.com/api/cells/42" \
  -H "Authorization: Bearer ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{"value":"new value"}'
curl -i -A "MyApp/1.0" -X DELETE "https://bbaccounts.unaux.com/api/cells/42" \
  -H "Authorization: Bearer ACCESS_TOKEN"

Ответы списка не содержат value; загрузите cell по ID, чтобы прочитать значение. Project-bound и user-bound cell’ы с одинаковым ключом — разные cell’ы.

Teams API

Прочитать команды владельца токена. Требуется верифицированный проект и scope teams. Токен идентифицирует аккаунт.

curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/teams" \
  -H "Authorization: Bearer ACCESS_TOKEN"

# Token in URL also works
curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/teams?access_token=ACCESS_TOKEN"

Возвращает count и teams. Каждая команда включает id, name, slug, вашу role, subscribed и members.

Проекты и ключи

Для чего вкладка Projects

Вкладка Developer → Projects — место, где вы настраиваете и управляете приложениями, использующими bbaccounts OAuth/API.

  • Создайте проект — зарегистрируйте приложение/игру/сервис, который будет авторизовать пользователей через bbaccounts.
  • Redirect URI — добавьте точные callback URL, куда bbaccounts вернёт пользователя после авторизации.
  • Client credentials — создавайте именованные ключи; получите client_id и одноразовый client_secret для обмена OAuth-токенов.
  • Брендинг/настройки — редактируйте название проекта, описание, логотип и другие детали, видимые пользователям.
  • Управляйте доступом — отзывайте ключ, ротируйте credentials или удаляйте проект, когда он больше не нужен.

Доступ разработчика включается для аккаунта вручную. После включения страница разработчика позволяет создавать проекты, редактировать брендинг, регистрировать redirect URI и выпускать именованные client credentials. У проекта может быть до десяти активных credentials, чтобы можно было ротировать один без поломки другой интеграции.

Обычный credential получает secret, который показывается один раз при создании; если он потерян — отзовите ключ и создайте новый. У public client секрета нет вообще, и он обязан использовать PKCE. Используйте public-клиенты для desktop, CLI и browser-only приложений. Удаление проекта каскадно удаляет redirect URI, credentials, authorization codes, токены и согласия пользователей.

Аккаунты и восстановление

Аккаунты используют email и пароль. Поскольку этот инстанс не отправляет email, здесь нет ссылки подтверждения и письма для сброса. Каждый аккаунт получает 10 одноразовых recovery codes при регистрации; их можно пересоздать на странице безопасности с текущим паролем. Код сбрасывает пароль и расходуется при использовании.

Смена пароля завершает все остальные сессии. Сессии живут 30 дней и продлеваются при активности. Пользователи могут просматривать и отзывать устройства на странице безопасности, а также переключаться между аккаунтами, уже вошедшими на этом устройстве, без пароля. Каждый аккаунт может опубликовать публичный профиль по адресу /u/{username} с уникальным @username, коротким описанием, ролями, выбранными соцпровайдерами и до трёх витрин: текст, активные проекты, Badge Earned, медиа, GitHub-репозитории, ссылки, Friends или Best friends. Badge Earned и Friends всегда присутствуют и могут быть только выключены, но не удалены. Медиа — это загрузка изображения или видео и стоит 20 очков каждый раз; удаление не возвращает очки. Заработанные бейджи появляются только внутри витрины Badge Earned, как artwork с именем при наведении. Упоминание @username в описании или витрине ведёт на профиль.

Другие вошедшие пользователи могут лайкнуть профиль один раз. Лайк даёт 2 очков владельцу профиля, а каждая принятая дружба даёт 5 очков обоим. 15 очков покупают один дополнительный слот витрины (до десяти), или 15 очков покупают 10 дополнительных слотов друзей (до тридцати; базовый лимит — двадцать). Правила опубликованы на /rules; блокировки, rate limits, уникальность идентичностей и защита от self-like применяются без участия администратора.

Вход через соцсети

Вход через Google, GitHub и Discord появляется на странице входа, когда в инстансе настроены их credentials в private/config/config.php. Каждый провайдер привязывается только к существующему аккаунту, если совпадает подтверждённый email. Социальный вход никогда не создаёт аккаунт: сначала зарегистрируйтесь по email, затем подключите провайдера.

Подключённые провайдеры не заменяют пароль. Установите пароль в Безопасности, если регистрировались по email и паролю. Провайдера нельзя отключить, если это единственный способ входа.

Настройка провайдеров описана в основном README: создайте OAuth-приложение, укажите callback https://bbaccounts.unaux.com/oauth/social/google/callback, https://bbaccounts.unaux.com/oauth/social/github/callback, https://bbaccounts.unaux.com/oauth/social/discord/callback, https://bbaccounts.unaux.com/oauth/social/yandex/callback или https://bbaccounts.unaux.com/oauth/social/apple/callback и заполните нужные credentials. См. OAUTH-SETUP.md для каждого провайдера. Apple требует Service ID, Team ID, Key ID и private key. Steam не является провайдером входа: привяжите Steam ID в контактах профиля.

Примеры

Реальные пошаговые сценарии. Каждый пример ссылается на раздел API с подробностями.

1. Вход через bbaccounts (OAuth)

Используйте, когда приложению нужно идентифицировать пользователя. Нужен проект в Проекты и ключи.

  1. Создайте credentials проекта. В Developer → Projects создайте проект, добавьте Redirect URI и создайте credential. Сохраните client_id и client_secret. См. Проекты и ключи.
  2. Отправьте пользователя в bbaccounts. Перенаправьте браузер на Запрос авторизации: 
    GET https://bbaccounts.unaux.com/oauth/authorize?response_type=code
  &client_id=YOUR_CLIENT_ID
  &redirect_uri=https://your-app.example/callback
  &scope=profile%20email
  &state=RANDOM_STATE
  &code_challenge=BASE64URL_SHA256_VERIFIER
  &code_challenge_method=S256
  3. Пользователь одобряет доступ. bbaccounts перенаправляет обратно на ваш redirect_uri с ?code=...&state=....
  4. Обменяйте code на токены на вашем сервере. См. Обмен токена: 
    curl -X POST "https://bbaccounts.unaux.com/oauth/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "code=CODE_FROM_CALLBACK" \
  -d "redirect_uri=https://your-app.example/callback" \
  -d "client_id=YOUR_CLIENT_ID" \
  -d "client_secret=YOUR_CLIENT_SECRET" \
  -d "code_verifier=ORIGINAL_VERIFIER"
  5. Прочитайте профиль пользователя. Используйте полученный access_token с User info: 
    curl "https://bbaccounts.unaux.com/oauth/userinfo" \
  -H "Authorization: Bearer ACCESS_TOKEN"

2. Получить публичные данные профиля (без access token)

Используйте, когда нужен только публичный профиль по username. OAuth flow не нужен. См. Profile API.

curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/profile?username=timinside"

Приватные профили возвращают только базовые поля; остальные поля — none.

3. Получить свой профиль (с access token)

Используйте, когда у приложения есть токен пользователя и нужен профиль владельца токена. См. Profile API.

curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/profile" \
  -H "Authorization: Bearer ACCESS_TOKEN"

4. Выдать бейдж пользователю

Используйте, когда верифицированный проект хочет наградить пользователя. Нужен scope badges. См. Badges API.

  1. Создайте бейдж. На странице настроек проекта откройте Badges и создайте бейдж. Запомните его числовой ID (показан в списке бейджей).
  2. Выдайте по ID бейджа. 
    curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/badges/12/issue" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"timinside"}'
  3. Проверьте результат. Ответ содержит badge_id, username и slug. Повторная выдача безопасна.

5. Сохранить данные пользователя в storage cell

Используйте, когда верифицированному проекту нужно хранить небольшие per-user или per-project данные (до 256KB на cell). Нужен scope cells. См. Cells API.

  1. Создайте или обновите cell. Отправьте key, value и необязательный username, чтобы привязать к пользователю: 
    curl -i -A "MyApp/1.0" -X POST "https://bbaccounts.unaux.com/api/cells" \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key":"save_slot_1","value":"{\"level\":3}","username":"timinside"}'
  2. Прочитайте позже. Получите список по username/key или загрузите cell по ID: 
    curl -i -A "MyApp/1.0" "https://bbaccounts.unaux.com/api/cells?username=timinside&key=save_slot_1" \
  -H "Authorization: Bearer ACCESS_TOKEN"

Всё ещё не понятно?

Объясни как для чайника

Думай о bbaccounts как о владельце кнопки «Войти».

  1. Твоё приложение не хранит пароль пользователя. Когда кто-то хочет войти, твоё приложение отправляет его в bbaccounts.
  2. Пользователь входит в bbaccounts и нажимает «Разрешить». bbaccounts возвращает пользователя в твоё приложение с временным кодом.
  3. Твой сервер обменивает этот код на access token. Код — как одноразовый билет; access token — как временный пропуск.
  4. Твой сервер использует access token, чтобы спросить у bbaccounts, кто этот пользователь. Потом твоё приложение создаёт свою сессию/cookie для этого пользователя.

Важно: client_secret — это пароль сервера твоего приложения. access_token — временный пропуск пользователя. Никогда не путай их.

Если тебе нужна только публичная информация профиля по username, используй GET /api/profile?username=... — access token для этого не нужен.

bbaccounts — сервис идентификации и входа для подключённых проектов.
